# 17 — Packaging verification

**Status:** done

Prove the installer works for a user who has never seen the repo.

## Inputs

- `apps/desktop/electron-builder.yml`, `docs/architecture.md` §6, `CLAUDE.md` Windows notes.

## Deliverables

- `resources/icon.ico` (256×256 multi-size; a simple tangerine rounded square with an ink "C" in Fredoka is fine) wired via `win.icon`, and `productName`/`appId` confirmed.
- `pnpm dist` on this machine; then install `Cadence Setup x.y.z.exe` under a **separate Windows user account** (or a clean VM): first launch creates `%APPDATA%\Cadence\cadence.sqlite` and `logs/`, migrations run, onboarding appears, MIDI works with a plugged-in keyboard, audio plays, Today → Practice → Complete loop works, relaunch resumes state.
- `docs/release.md`: step-by-step release checklist (bump version in both `package.json`s, `pnpm check`, `pnpm e2e`, `pnpm dist`, smoke the installer, tag), the SmartScreen note, Defender exclusions for faster builds, Developer Mode note for first `pnpm dist`, and how to collect logs from `%APPDATA%\Cadence\logs` for bug reports.
- Verify `asarUnpack` shipped `better_sqlite3.node` and `extraResources` shipped `drizzle/` (inspect `dist/win-unpacked/resources`).

## Acceptance

- Installer runs on a clean profile with no dev tooling; app starts, migrates, and completes a level.
- Uninstall removes the app but leaves `%APPDATA%\Cadence` (document this).
- `docs/release.md` committed; task status flipped.

## Out of scope

Code signing, auto-update, Microsoft Store.

## Notes

Verified on the build machine (Windows 10 19045, Electron 44.5.1, electron-builder 26.15.3) on 2026-10-01:

- **Icon**: `apps/desktop/resources/icon.ico` (16/32/48/64/128/256; BMP entries below 256, PNG at 256) is generated by `apps/desktop/scripts/generate-icon.mjs` (`pnpm --filter @cadence/desktop icon`, no dependencies). The "C" is a geometric round-capped arc in Fredoka's style rather than a rasterized Fredoka glyph, which would need a font rasterizer dependency. Wired via `win.icon`; dev/e2e runs pass it to the BrowserWindow. `Cadence.exe` shows the icon.
- **Names**: `appId: com.harry.cadence`, `productName: Cadence` in `electron-builder.yml`, and `"productName": "Cadence"` added to `apps/desktop/package.json` (without it, `userData` is derived from the package `name`). The packaged app logs `userData=C:\Users\Harry\AppData\Roaming\Cadence`.
- **Package**: `pnpm dist` → `apps/desktop/dist/Cadence Setup 0.1.0.exe`, 124,053,578 bytes. `resources/app.asar.unpacked/node_modules/better-sqlite3/prebuilds/win32-x64.node` is unpacked. better-sqlite3 13 ships N-API prebuilds, so there is no `build/Release/better_sqlite3.node`; its loader picks the prebuild. `resources/drizzle/0000_brave_iron_lad.sql` and `meta/` are shipped.
- **Migration logging** (new): `main/db.ts` counts `__drizzle_migrations` rows before and after migrating, and startup logs `Database <path>: applied N migration(s), M total` (unit test `main/db.test.ts`).
- **Clean-profile smoke (emulated)**: `%APPDATA%\Cadence` did not exist beforehand. `win-unpacked\Cadence.exe` with no `CADENCE_USER_DATA`/`CADENCE_E2E` created `cadence.sqlite` (WAL) and `logs\main.log`, logged `applied 1 migration(s), 1 total` and `dev=false e2e=false; 14 IPC channels` (no `dev.seed`), no errors, and showed the onboarding screen. Relaunch logged `applied 0 migration(s), 1 total`.
- **Installer**: `"Cadence Setup 0.1.0.exe" /S /D=<temp>` exited 0, registered the HKCU uninstall key `Cadence 0.1.0`, and created Start menu and desktop shortcuts. After `%APPDATA%\Cadence` was removed, the installed exe recreated it and migrated (same log lines). `Uninstall Cadence.exe /S` exited 0 and removed the install folder, uninstall key and both shortcuts. **`%APPDATA%\Cadence` was left in place** (documented in README and `docs/release.md`).
- `docs/release.md` holds the release checklist, SmartScreen, Defender, Developer Mode, uninstall, log collection and `pnpm rebuild:native` notes.

Not verified here (needs a person at the machine):

- Installing under a separate Windows account or VM. This was emulated on the dev account with a fresh `%APPDATA%\Cadence`, but dev tooling stays on PATH. The app itself needs none: Electron, the native module and migrations are all inside the package.
- Interactive checks: entering a name in onboarding, MIDI with a plugged-in keyboard, audio output, a full Today → Practice → Complete loop, and resume after relaunch with real progress. These are covered against the built (unpackaged) app by `pnpm e2e`, not against the installer. Run step 8 of `docs/release.md` once by hand.
