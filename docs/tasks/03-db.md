# 03 — `@cadence/db`

**Status:** done

Drizzle schema, first migration, and repositories that implement the port interfaces `@cadence/core` will declare. Because `core` (Task 04) comes after this task, **define the port interfaces in this task** in `packages/core/src/ports.ts` (types only, no logic) so `db` can implement them; Task 04 then builds services on those ports.

## Inputs

- `docs/engine.md` §3 (tables, columns, keys) and §4 (what services need from repos).
- `docs/architecture.md` §5 (data layer rules, migration strategy).
- Drizzle `sqlite-core` + `drizzle-orm/better-sqlite3` + `drizzle-orm/better-sqlite3/migrator`.

## Deliverables

- `packages/core/src/ports.ts` — `Clock { now(): number; today(timezone: string): string }`, and repo interfaces: `ProfileRepo`, `TrackSettingsRepo`, `StepProgressRepo`, `LevelProgressRepo`, `SessionRepo` (sessions + session_steps), `XpRepo`, `DayLogRepo`, `PlanRepo` (daily_plans + plan_blocks), plus a `UnitOfWork`/`transaction(fn)` helper. Also `packages/core/src/dates.ts`: `localDay(epochMs, timezone)` via `Intl.DateTimeFormat`, `addDays(day, n)`, `daysBetween`.
- `packages/db/src/schema.ts` — all tables from engine.md §3 with the listed indexes/uniques; integer-mode timestamps/booleans; text enums.
- `packages/db/src/client.ts` — `openDatabase(path | ':memory:')` applying `journal_mode=WAL` (not for memory) and `foreign_keys=ON`; returns `{ sqlite, db }`.
- `packages/db/src/migrate.ts` — `runMigrations(db, migrationsFolder)`.
- `packages/db/drizzle/0000_*.sql` generated with `pnpm db:generate` and committed.
- `packages/db/src/repos/*.ts` — one file per port, implemented with Drizzle; `createRepos(db)`.
- Tests in `packages/db/test/`: open `:memory:`, run real migrations, exercise every repo method (upsert semantics, unique constraints, index-backed queries like `dueOn ≤ today`).

## Acceptance

- Migrations apply on a fresh DB and re-running is a no-op.
- Every repo method has a test; `onConflictDoUpdate` used for upserts (no `INSERT OR REPLACE`).
- No SQLite-only SQL in repo code (keep the Postgres path open).
- `localDay` tests: 2026-03-08T07:30Z in `America/Los_Angeles` is `2026-03-07`; same instant in `Europe/Berlin` is `2026-03-08`.
- `pnpm check` green.

## Out of scope

Business rules (scheduling math, plan building) — Task 04. Wiring into Electron — Task 05.

## Notes

- Timestamps are plain `integer` epoch-ms columns typed `number` (not drizzle `timestamp_ms` → `Date`), so they line up with `Clock.now(): number`.
- Unit of work is `Repos.transaction(fn)` (synchronous; wraps drizzle's better-sqlite3 transaction, so nested calls become savepoints).
- Full-row upserts (`trackSettings`, `stepProgress`, `levelProgress`, `dayLog`, `plans.save`) replace every non-key field on conflict; `stepProgress.upsert` keeps the original `id`/`createdAt`. `dayLog.increment` adds counters on conflict (column + value, portable SQL). `sessions.upsertStep` is idempotent on `(session_id, ordinal)` and only writes `played_back` when provided; `markPlayedBack` flips it once and reports whether it changed.
- `XpRepo.award` does the ledger insert + `profile.xp_total` increment in one transaction (engine.md §4 XpService).
- Additions beyond engine.md §3: FKs `session_steps.session_id → sessions` (cascade), `plan_blocks.day → daily_plans` (cascade), `xp_ledger.session_id → sessions` (set null). `sessions.question_order` is a JSON text column (`string[]`).
- Schema row types are asserted equal to the core port row types with `expectTypeOf` in `packages/db/test/migrations.test.ts`.
- Tests resolve the migrations folder via `import.meta.dirname` (no `node:*` import in packages).
