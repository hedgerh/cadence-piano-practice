# UI system

Designs in `docs/handoff/design/*.dc.html` are the source of truth for layout, copy, colors and states. They do **not** render standalone (missing `support.js`, template runtime); read the inline styles and the `<script>` blocks as specs. Cited as `File:line`.

## 1. Tokens — `renderer/styles/tokens.css`

Every hex in the nine designs is a variable (see the file). Highlights: `--ground #FAF7F2`, `--ink #211B16`, `--muted #6B615A`, `--line #EFE8DF`, `--line-strong #E6DED4`, `--shadow-card #E9E0D5`, `--sand #F1EBE3` (track bg, segmented well, disabled chips, inner-ring minors, tried keys), `--sand-deep #EDE5DB` (empty segments), `--dune #D9CFC3` (dashed borders, keyboard shadow), `--tangerine*`, `--teal*`, `--lavender*`, `--sun`, `--key-held` (= sun; decision). Shadows are hard (no blur). `qualityColor(quality)` is the single mapping major → tangerine, minor → teal, diminished → lavender.

Fonts: `'Fredoka Variable'` 600/700 for headings and numerals; `'Nunito Variable'` 600–800 elsewhere. Bundled via `@fontsource-variable/*`.

Global CSS (`global.css`) mirrors each design file's globals: `body{margin:0}`, link colors, `cad-pulse` keyframes. **No global `box-sizing` reset** — set it per component exactly as the design does.

### PianoKeyboard — `components/music/PianoKeyboard.tsx`

- `variant: 'two-octave'` (C3–B4, 14 whites, **661px**, r10, `--sh-keyboard`) | `'one-octave'` (7 whites, **332px**, r8, no shadow). `states: Record<noteId, 'idle'|'held'|'hint'|'correct'|'tried'|'home'>`.
- Container `position:relative; display:flex; gap:3px; padding:3px; background:--ink`. White key 44×150 (one-octave 44×120), `border-radius 0 0 7px 7px` (6px), label 11/800 `--key-label`, bottom-aligned. Black key 28×95 (28×76), absolute `top:0`, `left = 47·(i+1) − 12.5` px where `i` is the index of the white key to its left; rendered after whites. Lit black adds `inset 0 0 0 3px --ink`.
- Fill by state: hint tangerine · correct teal · home teal · tried `--sand` · held `--key-held`. Priority `correct > home > hint > held > tried`.
- Test: the ten computed lefts equal `[34.5, 81.5, 175.5, 222.5, 269.5, 363.5, 410.5, 504.5, 551.5, 598.5]` (Practice:149–151).

## 4. MIDI & audio in the renderer

- `midi/MidiInput.ts`: `interface MidiInput { status$, held$, events$, start(), stop() }`; `NoteEvent = {type:'on'|'off', midi, velocity, at}`; `MidiStatus = unsupported | requesting | denied | no-device | connected{deviceName, deviceId}`.
- `WebMidiInput`: `requestMIDIAccess({sysex:false})`; `0x90` vel>0 → on, `0x80` or vel 0 → off; `onstatechange` hot-plug. Listens to one input: the preferred port (id, then name), else the first connected; `devices$` lists every connected port; switching or losing the port clears held notes. Sustain (CC64) ignored.
- `KeyboardMidiInput`: `a w s e d f t g y h u j k o l p ;` = C4…E5, `z`/`x` octave; active in dev and when no device. `FakeMidiInput`: `press/release` for tests; `window.__cadenceDev.midi` when `CADENCE_E2E=1` or dev.
- `midiStore` (Zustand) composes real device → keyboard fallback. Hooks: `useMidiStatus`, `useHeldNotes`, `useMidiEvents`.
- MidiPill: connected → teal-deep dot (pulsing on task screens) + name; no-device → dune "No keyboard found"; requesting → pulsing dune "Looking for keyboards…"; denied → "MIDI access blocked". Task 16: the live pill is a button (40px + 2px border = 44px) opening a "Keyboards" menu (`menuitemradio` per port, checked = active; empty state explains why and mentions the computer keys); a caret shows when several ports are connected; long names ellipsize. The pick is saved with `me.update {midi}` and restored at launch (`midi/devicePreference.ts`).
- Audio: `Synth` interface + `WebAudioSynth` (see engine.md §7), `AudioContext` resumed on first gesture and inside every `play`.

## 5. Fidelity verification

Probes (`e2e/probes.ts`) assert computed styles per screen: header 76 + border; wordmark 700/28 Fredoka; pills 40; card radius/border/shadow strings; primary button 56/60 + radius + shadow; keyboard 661/332 and key sizes + the ten black-key lefts; circle node sizes 72/84/40 and positions within 1px; segments 10px + colors; h1 44/40/48; numeral 104. Pixel diffing against the originals is optional (would need a `support.js` shim); probes are the gate.
